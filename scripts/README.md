# Five-stage experiment scripts

The numbered scripts run Full FT → Unlearn → Replace → Rank → Merge.
Each script lists its model, data splits and output settings before the commands.
`common.sh` sets repository paths, model and tokenizer defaults, the distributed port, and evaluation data paths.

## Settings

| Setting | Default |
|---|---|
| `MODEL` | `Llama-3.2-1B-Instruct` |
| `METHOD` | `NPO` |
| `FORGET_SPLIT`, `RETAIN_SPLIT`, `HOLDOUT_SPLIT` | `forget05`, `retain95`, `holdout05` |
| `OUTPUT_ROOT` | `outputs` under the repository root |
| `SOURCE_OUTPUT_ROOT` | `OUTPUT_ROOT`; stages 3–5 can read existing checkpoints here |
| `BASE_MODEL_PATH`, `TOKENIZER_PATH` | The model's Hugging Face ID; local paths are also supported |
| `BATCH_SIZE` | `4` per training device |
| `ACCELERATE_CONFIG` | `configs/accelerate/default_config.yaml` (two GPUs) |
| `SAVE_MODELS` | `false`; `true` saves a Merge checkpoint for every k |

For custom model configurations, set `BASE_MODEL_PATH` and `TOKENIZER_PATH`.
Keep model, split and output settings consistent across stages.
Training defaults to four gradient accumulation steps with gradient checkpointing disabled.
The custom evaluator inside training runs only with a single process. The default two-GPU
training skips it; stages 1 and 2 perform separate reference and test evaluations afterward.
Pass explicit Hydra overrides to change training settings:

```bash
bash scripts/02_unlearn.sh trainer.args.gradient_accumulation_steps=8
bash scripts/01_finetune.sh \
  trainer.args.do_eval=false \
  trainer.args.eval_on_start=false \
  trainer.args.eval_strategy=no
```

Stage 1 passes training overrides to both training calls. Its separate retain-reference evaluation still runs.

## Evaluation protocol

Stages 1 and 3 call `src/select/prepare_tofu_data.py`, writing to `datasets/legacy_sh/` by default.
The generator reproduces the original `select_data_tofu.py` slices used by the shell pipeline,
not the later `*_v/*_t` partition variants. Data can also be prepared without loading a model:

```bash
python src/select/prepare_tofu_data.py --output-dir datasets/legacy_sh
```

Source data comes from Hugging Face or the directory specified by `CRU_TOFU_DATA_ROOT`.
Local sources must include `forget05.json`, `forget05_perturbed.json`, `holdout05.json`,
`retain_perturbed.json`, `forget01.json`, `forget01_perturbed.json`, and `holdout01.json`.
Both JSON arrays and JSONL are supported. The test split uses the original HF forget01;
it is not constructed by assuming it equals the final 40 rows of forget05.
Identical existing data is reused. A file lock prevents concurrent jobs from overwriting each other.

| Purpose | Forget data | Retain data for MU | Holdout data |
|---|---|---|---|
| Replace / ranking | First 160 rows of forget05, named forget04 | First 320 rows of retain_perturbed | Rows 40–199 of holdout05 |
| Final test | Original HF forget01 and forget01_perturbed | Rows 320–399 of retain_perturbed | Original HF holdout01 |

`forget04` is the compatibility name for the fixed validation split `forget05[:160]`.
It denotes 4% of the complete TOFU dataset, not 4% of forget05.
The real_authors and world_facts datasets and the harmonic mean of nine MU components
retain their original definitions. MU evaluates the current model directly; it does not
compare against retain95 or retain99 logs.

FQ always reads `outputs/eval/tofu_<model>_retain95/TOFU_EVAL.json`, generated by the
retain95 checkpoint on the complete forget05 split. This reference distribution is not
split into separate validation and test references.
For the ES retain metric, final testing uses `retain_split=retain99`, while Replace uses
`retain_split=holdout04`. These evaluator settings do not change the retain95 checkpoint
or reference-log path used by the shell scripts.

Training uses full, forget05 and retain95. Training-time evaluation follows the explicitly
passed forget/retain splits. Final evaluation results go under `outputs/legacy_sh/`.
`split_manifest.json` records source and generated-file hashes; different existing data is not overwritten.
Set `CRU_EVAL_DATA_ROOT` to relocate generated splits and `CRU_TOFU_DATA_ROOT` to supply source files.

## 1. Fine-tuning

`01_finetune.sh` prepares evaluation splits, trains Full FT on full data, and separately
trains the retain-only reference from the same pretrained model. It generates reference
logs on forget05, then evaluates retrain and Full FT on the test splits.
Checkpoints are saved to `outputs/finetune/tofu_<model>_full` and
`outputs/finetune/tofu_<model>_<retain_split>`. Reference logs are saved to
`outputs/eval/tofu_<model>_<retain_split>/TOFU_EVAL.json`.

Run this stage once for a given model and training setup. Reuse complete Full FT and
retain95 checkpoints for subsequent unlearning methods; do not repeat stage 1 solely
to change the unlearning objective. Existing checkpoints can also be evaluated separately
using the evaluation commands in stage 1.

## 2. Unlearning

`02_unlearn.sh` starts from Full FT and writes the selected method's checkpoint to
`outputs/unlearn/tofu_<model>_<forget_split>_<method>`.
NPO defaults to the forget-only objective (`alpha=0`). Explicitly enable optional retain loss with:

```bash
METHOD=NPO bash scripts/02_unlearn.sh trainer.method_args.alpha=1.0
```

This changes the training objective. Keep results from different objectives in separate runs.

## 3. Independent layer replacement

`03_replace.sh` starts from Full FT and copies one layer at a time from Unlearn.
Both models are loaded once, and the original layer is restored before evaluating the next candidate.
Outputs include `outputs/legacy_sh/replace/<task>/layer-<i>/TOFU_SUMMARY.json` and detailed logs.
The base is Full FT, not the retain-only model.

## 4. Layer ranking

`04_rank.sh` ranks MU and signed FQ separately, adds their ranks, and saves the complete
ordering to `outputs/legacy_sh/rankings/<task>.json`. Missing or non-finite scores cause an error.
Ties in the rank sum favor the smaller physical layer index.
This ranks **layers**; it does not choose a final **k**.

## 5. Cumulative Merge evaluation

`05_merge.sh` invokes `src/merge_sweep.py` once. Full FT is loaded on the evaluation device,
while Unlearn is loaded on CPU. Each new k copies one more layer in ranked order.
The resulting parameters match independently building each ranked prefix; all non-layer
parameters remain from Full FT. Consequently, k=L need not equal the complete Unlearn model.
The random seed is reset before each evaluation, as with separate evaluation processes.

The default pipeline plots every k without choosing a best point:

```text
outputs/legacy_sh/merge_sweep/<task>/
├── ranking.json
├── merge_curves.png           MU vs k and FQ vs k, in two panels
├── merge_curves.pdf
├── merge_curves.csv
└── k-<k>/eval/
    ├── TOFU_EVAL.json
    ├── TOFU_SUMMARY.json
    └── CRU_MERGE.json
```

`SAVE_MODELS=true bash scripts/05_merge.sh` additionally saves checkpoints in `k-<k>/model/`.
Weights are not saved by default.

To resume an interrupted Merge sweep, rerun `bash scripts/05_merge.sh` with the same settings.
Completed results are verified and skipped; incomplete candidate directories are archived
under `incomplete/` before retrying. Previously ranked layers are still copied when resuming,
so each candidate has the correct cumulative parameters.
Changed configuration, ranking, reference logs or local checkpoint metadata prevents reuse.
Completed artifacts are verified by SHA256. Runs without `sweep_manifest.json` cannot be resumed automatically.

To evaluate existing checkpoints in a separate output directory:

```bash
export SOURCE_OUTPUT_ROOT=outputs
export OUTPUT_ROOT=outputs_new
bash scripts/03_replace.sh
bash scripts/04_rank.sh
bash scripts/05_merge.sh
```

## Optional evaluation and analysis

Run commands from the repository root.

### Optional k selection under a MU requirement

Choose a minimum acceptable MU before looking at test results. Using a complete validation
Merge sweep, select the highest signed FQ among candidates with `MU >= min_mu`.
Ties favor smaller k. If no candidate meets the requirement, no selection is made and the
threshold is not relaxed. Candidates cover k=1..L; no unmeasured k=0 point is invented.

```bash
python src/select_k.py \
  --results-dir /path/to/separate_validation_merge_sweep \
  --min-mu YOUR_MIN_MU
```

Replace `YOUR_MIN_MU` with your validation requirement; it has no default.
`selection.json` records the threshold, candidates, selected k and layers, or `no_feasible_candidate`.
The selector reads existing scores and does not run GPU evaluation. The five-stage pipeline
never invokes it. Stage 5 produces test curves by default, and test-marked results are rejected
by the selector. Supply a separate validation sweep and evaluate the selected model on test data afterward.

To export one selected checkpoint, replace `K` with the selected value:

```bash
python src/merge.py \
  --base-model outputs/finetune/tofu_Llama-3.2-1B-Instruct_full \
  --unlearned-model outputs/unlearn/tofu_Llama-3.2-1B-Instruct_forget05_NPO \
  --ranking outputs/legacy_sh/rankings/tofu_Llama-3.2-1B-Instruct_forget05_NPO.json \
  --k K \
  --output outputs/selected_model
```

### Original and Full FT reference evaluations

**Original** means evaluating the complete Unlearn checkpoint directly.
**Baseline (k=0)** means evaluating the actual Full FT checkpoint.
The commands below use stage 5's test splits: forget01, holdout01, retain99 and retain_perturbed_80,
with retain95 reference logs for FQ. Stage 3 uses validation data and cannot share these test reference lines.
Stages 1 and 2 already produce Full FT, retrain and Unlearn test results; these commands are for
separate evaluation of existing checkpoints:

```bash
MODEL=${MODEL:-Llama-3.2-1B-Instruct}
METHOD=${METHOD:-NPO}
FORGET_SPLIT=forget05
RETAIN_SPLIT=retain95
HOLDOUT_SPLIT=holdout05
OUTPUT_ROOT=${OUTPUT_ROOT:-outputs}
source scripts/common.sh
setup_eval_protocol
python src/select/prepare_tofu_data.py --output-dir "$CRU_EVAL_DATA_ROOT"
SOURCE_OUTPUT_ROOT=${SOURCE_OUTPUT_ROOT:-$OUTPUT_ROOT}
TASK="tofu_${MODEL}_${FORGET_SPLIT}_${METHOD}"
REFERENCE="$SOURCE_OUTPUT_ROOT/eval/tofu_${MODEL}_${RETAIN_SPLIT}/TOFU_EVAL.json"

for KIND in baseline original; do
  if [[ $KIND == baseline ]]; then
    CHECKPOINT="$SOURCE_OUTPUT_ROOT/finetune/tofu_${MODEL}_full"
  else
    CHECKPOINT="$SOURCE_OUTPUT_ROOT/unlearn/$TASK"
  fi
  python src/eval.py \
    experiment=eval/tofu/default model="$MODEL" task_name="${TASK}_${KIND}" \
    forget_split=forget01 holdout_split=holdout01 retain_split=retain99 \
    forget_perturb_split=forget01_perturbed retain_perturb_split=retain_perturbed_80 \
    model.model_args.pretrained_model_name_or_path="$CHECKPOINT" \
    model.tokenizer_args.pretrained_model_name_or_path="$TOKENIZER_PATH" \
    retain_logs_path="$REFERENCE" \
    paths.output_dir="$EVAL_ROOT/${KIND}_eval/$TASK/test"
done
```

`--baseline-summary` adds k=0 only to the Merge test panel. A single `--original-summary`
cannot be shared between validation and test panels under this protocol.

### Additional analyses

The tools below have their own input conventions and are not required for the five-stage pipeline.
Use `src/select/select_indices.py` for additional index-selection analyses:

```bash
python src/select/select_indices.py --mode partition --models 1B-NPO
python src/select/select_indices.py --mode validation --models 1B-NPO
python src/select/select_indices.py --mode layer --models 1B-GA,3B-GA,1B-NPO,3B-NPO
python src/select/select_indices.py --mode muse --models BOOKS-GA,BOOKS-NPO
```

See the [plotting guide](../visualization/README.md) for complete Replace/Merge figures.

MIA registers `mia_min_k` and `mia_min_k_plus_plus`, implemented in

### Input paths and optional evaluators

Inputs default to the current repository. Set `CRU_INPUT_ROOT` to read checkpoints and datasets
from another directory; generated outputs remain in the current repository.
For optional lm-eval evaluation, install `lm-eval` in the current environment or set
`CRU_LM_EVAL_ROOT` to a source directory containing the `lm_eval` package.
